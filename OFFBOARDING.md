# Offboarding

Este documento define como debe cerrarse cada jornada de trabajo en `Admira Next Dream Team`.

## Objetivo

El offboarding asegura que el trabajo del dia no se quede solo en la cabeza de una IA o de una persona. Su funcion es dejar continuidad real para el siguiente relevo.

## Regla diaria de salida

Al terminar cada bloque importante de trabajo y especialmente al cerrar el dia, debe hacerse un offboarding.

Ese cierre debe incluir como minimo:

1. un resumen corto de lo que se ha hecho,
2. lo que ha cambiado en el proyecto,
3. que queda pendiente,
4. riesgos, bloqueos o decisiones abiertas,
5. una actualizacion diaria de la web del proyecto,
6. publicacion de esa salida en GitHub Pages,
7. limpieza de cache y validacion de la URL publica,
8. y abrir la pagina web resultante para que pueda verla la persona que coordina el proyecto.

## Actualizacion obligatoria de la web

Igual que el onboarding es obligatorio al entrar, el offboarding debe dejar reflejada la actualizacion diaria en la web principal del proyecto.

La idea es que la web de `Admira Next Dream Team` no sea solo una presentacion del equipo, sino tambien una ventana viva del estado del proyecto.

Esa regla debe leerse junto con `INSTRUCCIONES.md`, porque la entrega visible forma parte del comportamiento esperado y no solo del cierre.

## Apertura obligatoria de la web al cerrar

Cada vez que se actualice la web y se complete el offboarding, debe abrirse la pagina resultante para revision visual inmediata.

La referencia valida para esa revision debe ser la URL publica final, ya actualizada en Pages y comprobada despues de limpiar cache.

## Principios del offboarding

- Dejar contexto claro para la siguiente IA.
- No asumir que el siguiente relevo recordara el historial.
- Escribir decisiones, no solo tareas.
- Hacer visible el avance real del proyecto.
- Cerrar cada jornada con una huella util y reutilizable.

## Plantilla sugerida

### Resumen del dia

- Que se avanzo hoy.

### Cambios realizados

- Archivos o areas actualizadas.

### Pendientes

- Lo siguiente que conviene hacer.

### Riesgos o dudas

- Bloqueos, preguntas o decisiones abiertas.

### Actualizacion web

- Confirmar que la web principal del proyecto refleja el cierre del dia.
- Confirmar que la version publicada en Pages ya se ve en la URL publica tras limpiar cache.
- Confirmar que la URL publica queda abierta en navegador para supervision.
